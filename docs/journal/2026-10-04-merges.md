# 2026-10-04 · Unblocking and merging the foundation PRs

### D-93 · Root cause confirmed: unverified commits blocked every merge

- **Action (maintainer):** Registered the commit-signing key on GitHub as a _Signing Key_. Its fingerprint was checked against the key on the maintainer's machine.
- **Result:** GitHub re-verified every existing commit (`unknown_key` → `valid`), and all blocked PRs changed from BLOCKED to CLEAN.
- **Cause:** "Require signed commits" refuses to merge a PR that contains unverified commits, even with a squash merge, which GitHub signs itself. Why the first PR merged under the same conditions is still unexplained.
- **Lesson:** "Unknown key" isn't permanent. GitHub re-checks such commits once the key appears, so registering a key late also fixes past commits.

### D-95 · Require the CI gate, and up-to-date branches (autopilot)

- **Decision:**
  - The `main` ruleset now requires the `required` check from GitHub Actions; approved as part of D-80.
  - It also requires branches to be up to date with `main` before merging (autopilot).
- **Why:** Every PR is then tested against exactly the `main` it lands on, so "each PR passed, but together they break" can't happen. With stacked PRs, `main` is merged into each child anyway, so the extra cost is one CI run per merge.
