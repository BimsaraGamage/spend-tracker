# 2026-10-04 · Phase 0: CI and security workflows

Decisions made while building the CI and security workflows. ★ marks the recommended option. Entries without a prompt are decisions taken on **autopilot**, or **directions** from the maintainer.

### D-71 · Git hooks failed outside Node 24 (autopilot fix)

- **Found by:** Commits on the CI branch silently failed. The pre-commit hook called `pnpm`, which only exists under the Node version pinned in `.nvmrc`. With nvm defaulting to an older Node, as on the maintainer's machine, or when committing from an editor's Git panel, every commit would have been blocked with `pnpm: not found`.
- **Decision:** Document a personal `lefthook-local.yml` whose `rc` file loads nvm and switches to the `.nvmrc` version, and gitignore both files (autopilot). Applied in the tooling PR, where the hooks were introduced.
- **Why:** It fixes the problem for anyone using nvm without changing their global setup.
- **Detail:** Two first attempts failed. lefthook's version-matched docs showed that the rc path must be **absolute**, and that the rc is built into the hook scripts at install time, so hooks must be reinstalled with `lefthook install -f`.
- **Lessons:**
  - Hooks run in the environment that started git, not necessarily your terminal. Hooks that break in normal use get bypassed, so make them self-sufficient.
  - Verify every action's result. A helper that swallowed errors hid the failed commits.

### D-72 · Direction: stacked pull requests

- **Direction (maintainer):** Follow the stacked-PR approach, if it suits.
- **Action:** Confirmed, since each foundation PR depends on the one below it (tooling ← CI ← docs ← automation). The decision-journal PR stays independent because it depends on nothing. Fixes go into the PR that introduced the problem, and the PRs above it are rebased (see D-71).

### D-73 · One aggregator check gates merging (autopilot)

- **Decision:** A final `required` job depends on every CI job and fails if any failed or was cancelled. The `main` ruleset requires only this check (autopilot).
- **Why:** Rulesets match checks by name. With a single aggregator, adding or renaming jobs never needs a ruleset change, and jobs skipped by path filters don't block merges.

### D-74 · Dependency review thresholds (autopilot)

- **Decision:**
  - Fail on high or critical vulnerabilities, in both runtime and development dependencies.
  - Allow only licenses compatible with distributing an Apache-2.0 app through app stores: permissive licenses, MPL-2.0, and Creative Commons for data packages.
  - Copyleft (GPL, AGPL, LGPL, SSPL) and source-available licenses need a deliberate exception.
- **Why:** Build tools run on developer machines and in CI, so their vulnerabilities matter too. Lower severities still surface as Dependabot alerts without blocking work. App-store distribution and copyleft licenses conflict (D-17).

### D-75 · CodeQL scope (autopilot)

- **Decision:** Analyse JavaScript/TypeScript **and the GitHub Actions workflows** with the `security-extended` query suite, on PRs, on pushes to `main`, and weekly (autopilot).
- **Why:** Workflow injection is a real attack path in public repositories. The weekly run picks up newly published queries even when the code hasn't changed.

### D-76 · Publish the OpenSSF Scorecard results (autopilot)

- **Decision:** Publish the Scorecard results to the public Scorecard API and show them in code scanning (autopilot).
- **Why:** The repository is public anyway. Published results allow a Scorecard badge later and keep supply-chain hygiene visible.

### D-77 · PR-title check without a third-party action (autopilot)

- **Decision:** A small inline script checks the Conventional Commit title. The untrusted title is passed through an environment variable, and the job runs on `pull_request`, never `pull_request_target` (autopilot).
- **Why:** One less dependency with access to the repository. It was tested against 11 sample titles, including release-please's `chore(main): release …`.

### D-78 · Fix the pedantic zizmor findings (autopilot)

- **Decision:** Fix the five help-level findings that zizmor reports only at its strictest (pedantic) level: add a comment explaining each workflow permission, and add concurrency limits that cancel duplicate runs (autopilot).
- **Why:** Each is a one-line change, and the comments make the workflows self-explanatory to reviewers and learners.

### D-79 · Verify zizmor locally without installing system packages (autopilot)

- **Decision:** For a local zizmor run, download the release binary and check it against the SHA-256 digest GitHub records for the release asset, instead of installing through Python (autopilot).
- **Why:** The Python route needed a system package (`python3-venv`) and `sudo`. System changes on the maintainer's machine are off limits (D-45).
